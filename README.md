## Локальный запуск

Нужен Python 3.12 или новее. Из корня репозитория:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
source .venv/bin/activate
```

После активации:

```bash
python -m pip install -r requirements.txt
python manage.py check
python manage.py runserver
```

Открыть http://127.0.0.1:8000/. Для ДЗ2 миграции и база данных не требуются.
По умолчанию включён DEBUG и используются настройки для локальной разработки.
Названия переменных окружения перечислены в `.env.example`: `DJANGO_SECRET_KEY`,
`DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`. При локальном запуске Django читает их
из окружения процесса, файл `.env` сам по себе не загружается.
Например, в PowerShell: `$env:DJANGO_DEBUG="1"`, в bash: `export DJANGO_DEBUG=1`.

## Запуск через Docker Compose

Нужен Docker с Compose. Необязательно: скопировать `.env.example` в `.env`
(`Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в bash)
и задать свои значения. Compose автоматически прочитает `.env`.

```bash
docker compose up --build
```

Открыть http://localhost:8000/. Код подключён через bind mount, изменения
видны без пересборки. Для `/app/media` используется отдельный именованный volume.
Остановка: `docker compose down`. Команда сохраняет media volume.
`runserver` и эти настройки предназначены для учебного локального запуска.

## Структура

- `application/` - настройки Django и корневые URL.
- `core/` - вход, регистрация, профиль, базовый шаблон, общие include и пагинация.
- `questions/` - вопросы, ответы, теги, данные-заглушки и шаблоны карточек.
- `core/static/core/`, `questions/static/questions/` - исходная статика приложений.
- `/static/` - результат `collectstatic`, исключён из Git.
- `/media/` - пользовательские загрузки, исключены из Git.
- `public/` - сохранённый статический вариант ДЗ1, Django его не использует.

Общие стили, стили форм, профиля и вопросов разделены. Теги и участники
оформлены списками; для пользователя без аватарки выводятся инициалы.

## Страницы ДЗ2

| URL | Назначение |
| --- | --- |
| `/` | Новые вопросы, по 20 на страницу, новые первыми |
| `/hot/` | Вопросы по убыванию рейтинга |
| `/tag/css/` | Вопросы с указанным тегом по рейтингу |
| `/question/35/` | Вопрос и ответы, по 30 на страницу |
| `/login/` | Форма входа |
| `/signup/` | Форма регистрации |
| `/profile/` | Форма редактирования профиля |
| `/ask/` | Форма создания вопроса |

Примеры: `/?page=2`, `/hot/?page=3`, `/question/35/?page=2`.
`paginate(objects_list, request, per_page=10)` находится в `core/pagination.py`.
Пустые, нечисловые, отрицательные и выходящие за диапазон значения `page`
возвращают первую страницу. Неизвестный тег показывает пустой список,
несуществующий вопрос возвращает 404. В данных есть 125 вопросов и по 35 ответов,
чтобы можно было проверить переходы между страницами, включая списки по тегам.

В ДЗ2 данные не сохраняются: формы показывают макет и при POST поясняют,
что обработка появится в ДЗ4. Авторизация, поиск и голосование пока не реализованы;
кнопки голосования отключены. Юзерблок демонстрационный, на входе и регистрации - гостевой.
Во всех POST-формах установлен CSRF-токен.

## Проверка

```bash
python manage.py check
python manage.py test
python manage.py collectstatic --noinput
```

Тесты проверяют страницы, сортировку, фильтрацию тегов, 404, пагинацию,
граничные значения `page`, ссылки и наличие статических файлов.
